# Ditchfest Signs — фронтенд

Статический сайт на GitHub Pages: https://ditchfest.su (репозиторий theonrd/Ditchfest-Signs).
Голосования за карты Trackmania, топы игроков/мапперов, косметика/достижения (в разработке).

## Стек и хостинг
- Чистый HTML/CSS/JS, без сборщика и без фреймворка. Не предлагать Webpack/Vite/React —
  если понадобится сборка, это отдельное решение, обсуждается явно.
- Хостинг: GitHub Pages, ветка `main`, root `/`.
- Кастомный домен `ditchfest.su` — файл `CNAME` в корне обязателен, не удалять.
- Бэкенд — ОТДЕЛЬНЫЙ репозиторий/проект на Cloudflare Workers (`tm-votes`).
  Этот проект НИКОГДА не должен создавать серверный код — только вызывает Worker API.

## Структура репозитория
- `index.html` — главная страница
- `voting.html`, `top-mappers.html`, `top-players.html`, `profile.html`, `admin.html` — отдельные страницы
- `onboarding.html` + `js/onboarding.js` — пошаговое голосование для новичков:
  один выпуск на экране, прогресс хранится на сервере (`/api/onboarding`), в
  конце выдаётся ачивка
- `mapper.html` + `js/mapper.js` — публичная страница маппера (`?id=<accountId>`),
  ссылки на неё ведут из строк топа в `js/mappers.js`
- `js/achievements.js` — общий рендер бейджей достижений (`window.tmAchievements`),
  подключается перед скриптом страницы; сами тексты приходят из Worker
- `js/auth.js` — логин через Ubisoft/Trackmania OAuth, обёртка над Worker (`window.tmAuth`)
- `js/script.js` — UI-логика галереи/фильтров (не связана с авторизацией)
- `css/` — стили
- `res/` — изображения/ассеты (могут быть тяжёлыми — не просить Claude их "просматривать" целиком)
- `Signs/` — исходники/шаблоны генерируемых "знаков" (уточнить формат при первом использовании)

## Auth / API интеграция
- Все данные (голоса, топы, достижения) идут через Worker по адресу из `WORKER_URL`
  в `js/auth.js` (сейчас `https://tm-votes.onrd.workers.dev`).
- Токен — JWT, хранится в `localStorage` под ключом `tm_token`, подписывается Worker'ом.
  Фронтенд НЕ проверяет подпись — только читает payload для отображения.
- Формат вызовов: `Authorization: Bearer <jwt>` к эндпоинтам Worker API.
- **Важно:** `FRONTEND_URL` в Worker должен совпадать с реальным origin сайта (сейчас
  `https://ditchfest.su`). Если меняется домен — это правится в ДРУГОМ проекте (Worker),
  не здесь.

## Известные грабли (не наступать повторно)
- GitHub Pages при заданном `CNAME` жёстко редиректит `*.github.io` → кастомный домен.
  Это нормально, не пытаться "чинить" как баг.
- CORS ошибки почти всегда из-за рассинхрона `FRONTEND_URL` (Worker) и реального origin
  сайта — сначала проверять протокол (http vs https) и сам домен, только потом код.
- Не хардкодить абсолютные URL (`https://ditchfest.su/...`) в ссылках/JS — использовать
  относительные пути, чтобы сайт одинаково работал и на `github.io`, и на домене.

## Как эффективно работать с этим репо в Claude Code
- Не проси "посмотри весь репозиторий" — указывай конкретный файл/страницу.
- Правки в `res/` (картинки) не должны попадать в контекст как текст — это бинарники.
- Если меняешь что-то в auth-флоу — сначала проверь `js/auth.js`, поведение Worker
  описано в CLAUDE.md второго проекта, не дублируй эту логику здесь.
